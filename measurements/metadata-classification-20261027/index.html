    Final matched metadata-classification measurements

    With the reviewed correctness changes on both sides, the metadata fast path reduces median three-step CPU training time by 9.96% on MNIST and 18.43% on the small Transformer. Both API and subclass model tracing are enabled under ordinary collection (use_full_instr=False, retaining normal exclusions). Every one of the ten matched pairs improves. Hashing is unchanged.

    These final numbers supersede the initial study for the current implementation. The initial evidence remains in the parent output directory and in repository checkpoint bcf9bb82c3c11812336d1199dc699aa4ee6473e2. Do not compare timings across the studies to attribute additional improvements.

    • Transformer uses exact benchmark model definitions with bounded dimensions: embedding 32, two layers, two heads, feedforward 64, sequence length 16 and vocabulary 60 from the WikiText-2 prefix. Gradient clipping and the original manual SGD updates remain present.

Every case uses a fresh process and has a 90-second, 4-GiB sampled main-process RSS, 256-MiB trace limit; no case hit a limit.

The six correctness cases complete before measurement starts. Every paired/profiled run is checked directly against the corresponding plain candidate run: exact initial/final model-state digests and shapes, every loss and step ID, and Python/NumPy/PyTorch RNG state before training and after each step.     Asynchronous snapshot work

    File writes already use background threads on the subclass path. Moving only final JSON encoding off the producer offers little headroom in this study. The larger synchronous work inspects live objects and prepares their metadata. Moving those getters to a later worker after a shallow copy can observe changed values and change when errors occur. A future asynchronous tensor snapshot path needs owned snapshots, producer-stream ordering, bounded bytes/items, ordering per destination, and explicit worker-error and drain behavior. This change adds no asynchronous snapshot conversion. Per-attribute warning setup is the next measured implementation target, provided getter and warning semantics remain intact. Selective-checking overhead needs its own timing study.
