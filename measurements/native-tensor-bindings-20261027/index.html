    Native tensor bindings without repeated warning contexts

    The final implementation in signed commit 37f22e58954da403105c2c5510b7c7b6b3162ee6 reduces ordinary traced training time on the measured CPU and H100 workloads. It preserves native method binding and the existing metadata classifier, while avoiding the warning-managed getter for verified native tensor methods. JSON encoding, tensor hashing, instrumentation selection and the checker are unchanged.

    What changed and what remains

    Ordinary metadata conversion visits hundreds of Tensor methods. Their values usually contribute no output fields, yet generic lookup enters and exits a warning context for each one. The shortcut verifies exact Tensor/Parameter type, ordinary attribute lookup, native descriptor ownership, unchanged inheritance and an empty native instance dictionary. It then calls the descriptor type's native binding operation. Properties, custom lookup, subclasses, instance shadowing, foreign descriptors and TrainCheck-specific fields retain the original guarded getter.

    Only original MRO identities and live namespace proxies are cached. Current namespaces and native dictionary storage are rechecked for each attribute, so mutable values and descriptor results are not cached. A changed MRO disables the shortcut, including after bases are restored. The original classifier handles live primitive-type configuration exactly once. Native allocation failure retains NOT_FOUND/backoff behavior; internal assertions remain visible.

    The implementation deliberately retains the real bound object. A prior temporary value and its type must be released at their ordinary points, while the bound method must keep its receiver/function alive during a later property. Four regressions demonstrated that the earlier skip-based candidate changed these behaviors. All four fail on verbatim 287b3a2 sources on Python 3.10 and 3.12 and pass with the final binding implementation. A fifth regression verifies that a function's own __get__ attribute cannot override Python's native descriptor protocol. Historical CPU/H100 reports remain separately labeled; their faster skip-based measurements are not reused as results for the final implementation.

    This does not combine warning contexts around arbitrary properties, cache tensor metadata, change serialization, or introduce asynchronous dumping. The CPU component diagnostic reduces guarded getters from 1,192 to 60 per two conversions, while retaining all 28 field names per object. It preserves warning-filter contents/identity, the warning handler, tensor values and Python/NumPy/Torch RNG. Those are operation counts, not percentages of runtime attributed to warnings.

    Exact Tensor receivers account for all native bindings: 1,698,000 of 1,788,000 calls (94.97%). Exact Parameter receivers are unobserved, not a measured zero eligibility rate. The 152,048 other-receiver calls all use the fallback. Every successful shortcut still constructs the real method and runs classification. The count percentages do not attribute a fraction of total runtime to warnings.

    The collector preserves returned objects and exceptions, verifies bindings before installation and at restoration, and records zero exceptions escaping the binding helper or guarded getter. Internal NOT_FOUND handling remains unchanged and is not a separate exception counter. Its counted window takes 1.39489x its ordinary control's duration; diagnostic durations do not enter the performance table. Both corpora have 416,364 rows, 208,182 complete calls and 142,621,017 bytes with zero raw audit issues. Every per-step/API/event-kind count and per-step byte total matches, as do the complete recorded state and policy. This proves volume/integrity parity, not raw byte equality.

    State, traces and checking

    All 16 CPU traced runs match fresh plain controls' recorded initial/final model, gradient, optimizer and stored module state, RNG and losses. Every CPU MNIST run has 520 API records / 351,073 bytes; every Transformer run has 1,338 records / 1,014,134 bytes. Every call has one PRE and one POST, with no VAR records. All eight paired raw comparisons preserve complete ordered event sequences, fields, arrays and duplicates. Remaining differences are identities and timestamps; raw equality is false and cross-process identity-graph equivalence is not claimed.

    All nine H100 phases pass independent source, environment, command, policy, complete recorded state and loss checks. Seed-42 phases match the plain control; the seed-43 candidate matches its selective baseline. GPU tensor evidence includes names, shapes, dtypes and byte hashes, rather than archived full optimizer-state checkpoints. No identity, tensor value or array was removed to establish state parity.

    Raw comparisons of the first seed-42 selective pair and the seed-43 holdout uniquely match both complete ordered per-thread streams in each pair. Each variant has 416,364 records / 142,621,017 bytes in the first selective pair and 715,004 / 244,304,737 in the holdout. These full field comparisons cover those two pairs; raw/parser integrity audits separately cover all eight selective runs. No fields, array elements or duplicates are removed. Differences remain in identities/timestamps, constructor object_id and CUDA cuda_stream/native_handle values; raw equality is false. Constructor snapshots store literal id(receiver) in both source archives. All 800/1,600 stream-metadata observations preserve alias equality and a bijective observed handle correspondence. No structural/type/shape/array/exception payload differences occur, including the same two step-one _BypassDispatchCache exceptions. No global cross-process identity graph or inter-thread ordering equality is claimed.

    All eight raw/parser audits and eight checker phases completed successfully for this exact revision. The first seed-42 selective pair and seed-43 holdout each execute the same 722 frozen rules. Every cohort has 719 active rules: 718 passes and one violation; three rules are dormant. There are no checker errors, unknown outcomes, unobserved coverage or variable-check skips. Decision counts match across variants: 114,373 per ten-step corpus and 218,713 per holdout corpus. No variable precondition is requested, consistent with the API-only scope; this study does not establish model-tracker or variable-checking coverage.

    Within each corpus, all 722 complete checker_result values match structurally between observed and independent direct checking. The comparator preserves scalar types, fields, identities and array order; five legacy NaN literals match only at the same paths. Cross-variant rule outcomes and decision counts match, while complete checker results match for 721/722 rules. Rule 614 retains fresh-run identity/timestamp differences in its failure evidence; those fields are not removed or remapped to claim equality.

    The shared violation is rule 614, cuda.stream() always calls StreamContext.__init__(): its frozen child argument requires CUDA handle 385452624. Actual handles are 386050160/386062656 in the ten-step pair and 386059824/386070112 in the holdout. Both handle aliases agree, all other required fields match, and no fields are missing or extra. Dormant APIContain rules 216/276 require reference worker ID 23438301021888; rule 717 requires unequal threads and has zero decisions. Rules were not reinferred or filtered. This is unchanged frozen-rule behavior, not evidence of zero violations or universal rule activation.

    Offline validation ran on two separate labmach CPU cores, one native thread per worker and an 8-GiB process-group cap per lane. Its scheduling and operational timings are separate from inference-performance claims. Source and frozen input inventories remained unchanged. All 98 downloaded report files were verified.
